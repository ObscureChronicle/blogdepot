## 1. 网站整体设计风格

**设计定位**：独立游戏的"官网 + 设定百科 + 创作手记"三合一，面向已知/感兴趣的玩家，内容型、阅读型站点。

**视觉风格**：极简纸本风。暖米色底 `#F2F1EC` + 近黑文字 `#171717`（对比度 15.85:1），首页 Hero 为水墨晕染标题图，衬线正文（Newsreader）+ 无衬线元信息（Inter）。整体安静、克制，带古籍气质。

**布局与信息架构**：单栏居中，正文列宽 768px；顶部仅 3 个导航（主页 / 百科→`/tags/` / 日志→`/blog/`）+ 主题切换 ☯。

- 首页：标题 → Hero 轮播（2 张，可暂停）→ 游戏简介 → Steam 购买挂件 → 百科（5 条）→ 日志（3 条）→ 攻略视频（3 个 B 站嵌入）→ 页脚社交链接。
- 百科首页 `/tags/`：搜索框（Algolia）→ 分类检索（12 类）→ 音序检索（A–Z）。
- 词条页：面包屑 → 标题 → 别称表 → 能力（雷达图/柱状图，本传 vs 星命诀）→ 列传 → 兵种 → 登场战役 → 关联装备 → 上/下一篇 → 评论。

**色彩/字体/组件**：主色为黑白灰；词条页用浅蓝底色块标章节、蓝/红/绿区分阵营与熟练度、绿/黄区分两部作品。按钮多为细描边圆角胶囊（"所有百科条目""随机百科条目"）。

## 2. 现有设计的优点（建议保留）

| 优点 | 用户价值 |
|---|---|
| 水墨 Hero + 纸色底 + 衬线正文，主题统一 | 第一眼就建立"古风叙事"氛围，与游戏调性一致 |
| 正文 18px / 行高 32px，列宽 768px，主文字对比度 15.85:1 | 长文（列传、手记）阅读舒适，达 WCAG AAA |
| 面包屑（首页›百科›分类:人物›曹操）+ 上/下一篇带摘要 | 深层词条不迷路，支持"顺读"浏览 |
| 正文人名/物品自动变词条链接 | 百科型站点最核心的"跳读"体验，做得好 |
| 别称表含简/繁/日/英、拼音/注音/罗马字 | 照顾多语言玩家，信息完整 |
| 本传 vs 星命诀双雷达图并排 | 两作对比直观，是有特色的信息设计 |
| "随机百科条目 / 随机日志" | 低成本的探索乐趣，适合百科 |
| 轮播有暂停按钮、回到顶部按钮 44×44 | 符合可访问性与触控尺寸要求 |
| 暗色模式、移动端汉堡菜单可用 | 基础能力齐全 |
| 搜索即时下拉、关键词高亮 | 查找效率高 |

## 3. UI/UX 存在的问题

> 【客观】= 实测/测量得到；【主观】= 设计判断。

| 编号 | 问题所在 | 具体问题 | 对用户的影响 | 改善建议 |
|--|--|--|--|--|
| 1 | 分类列表 `/tags/biography/` | 【客观】每页仅 8 条，人物 443 条共 **56 页**；列表项只有名字，无头像/阵营/简介；标题显示为带引号的 `"人物"` | 想浏览人物几乎只能逐页翻，找人效率极低；引号像未处理的模板字符串 | 每页提到 50–100 条或改为一页全量 + 拼音锚点；条目改为多列网格并附 1 行信息（阵营/登场作品）；去掉标题引号 |
| 2 | 暗色模式·词条页按钮 | 【客观】"魏武挥鞭"等未选中切换按钮在暗色下为 文字 `#F2F1EC` on 背景 `#FFF`，**文字不可见** | 暗色用户看不到另一组称号/切换项 | 未选中态在暗色下改为透明底 + 浅色描边/文字 |
| 3 | 搜索入口 | 【客观】搜索框只在 `/tags/`；顶栏和移动端菜单都没有搜索入口 | 在词条/日志页想查别的词条，需先回百科首页，多一步；移动端更明显 | 顶栏加搜索图标（点开弹层复用现有 Algolia 组件），移动菜单同样加入 |
| 4 | 搜索结果 | 【客观】搜"曹操"，人物词条"曹操"排第 3，前面是"创作手记"；每条标题都带冗余后缀「｜后汉稽异录」；结果无分类标识 | 精确匹配被淹没；用户难以区分词条与日志 | 索引时去掉站名后缀；加 `category` 字段显示徽标（人物/日志…）；Algolia 设置标题完全匹配优先或词条类权重更高 |
| 5 | 词条页长度/导航 | 【客观】曹操页桌面 4510px、移动 5396px，有 7 个章节但**无目录/锚点** | 想看"登场战役"或"关联装备"要长距离滚动 | 标题下加章节锚点条（桌面可吸顶或右侧悬浮），移动端做成横向可滑动 chips |
| 6 | 移动端表格 | 【客观】375px 下别称表宽 552px，横向滚动但无任何提示，"English"列被藏起；另有 2 张表宽 375px 而内容区仅 327px，溢出页边距 | 用户不知道表格可横滑，遗漏信息；页面边缘不齐 | 给滚动容器加右侧渐隐阴影提示；溢出的两张表补 `overflow-x:auto` 包裹或移动端改为纵向卡片 |
| 7 | 首页·百科区块 | 【客观】展示的 5 条为"阿贵、AI目标、安乐公印、傲上、霸府"，即按拼音取前 5 | 首页最重要的百科入口展示的是随机性很强的条目，无法体现内容亮点 | 改为人工精选（主角/核心人物）或"最近更新"；或直接展示 12 个分类入口 |
| 8 | 百科首页 `/tags/` | 【客观】12 个分类 + 22 个字母全部单列纵排，页面 3243px；分类按字符排序（事典、人物、关卡…），"创作手记"（日志类）混在百科分类中 | 首屏只能看到 5 个分类；核心分类（人物、特性）不突出；日志与百科概念混淆 | 分类改为 3–4 列卡片网格，按重要度排序；音序改为一行字母导航条；"创作手记""更新日志"移到日志区或单独分组 |
| 9 | 首页性能 | 【客观】首页 5 个第三方 iframe（2 个 Steam + 3 个 B 站）均未设 `loading="lazy"` | 首屏加载慢、移动流量消耗大，B 站播放器在页面靠下却首屏即请求 | iframe 加 `loading="lazy"`；B 站改为"封面图+点击加载"（facade） |
| 10 | 用语一致性 | 【客观】页面标签显示"Tags \| 后汉稽异录""Blog \| 后汉稽异录"，搜索占位符"Search..."，汉堡按钮 aria-label"Open Menu" | 中文站中混入英文，浏览器标签/书签/读屏不统一 | 统一为"百科""日志""搜索词条…""打开菜单" |
| 11 | 评论区元信息 | 【客观】Waline 元信息 10px `#999`（对比度 2.52:1）、字数 12px（2.85:1） | 低于 WCAG AA 4.5:1，小字难读 | 在 `src/styles/waline.css` 覆盖为 ≥12px、颜色加深到 ≥4.5:1 |
| 12 | 词条页切换按钮状态 | 【主观】亮色下"奋武将军"选中态为灰底白字，未选中为白底黑字描边；灰底容易被读成"禁用" | 用户可能不知道当前选中的是哪个 | 选中态用主色/深色实底，或加下划线/勾选标记 |
| 13 | 暗色模式·图表 | 【客观观察】雷达图轴标签"气运/武勇"、柱状图坐标文字在黑底上为深灰，明显偏暗 | 暗色下数值标签难读 | 图表文字颜色跟随主题变量 |
| 14 | 首页语义 | 【客观】首页没有 `h1`（站名"后汉稽异录"不是 h1）；词条/日志页"←上一篇"用了 h2 | 影响 SEO 与读屏的大纲导航 | 首页站名或简介标题设为 h1；上/下一篇改用非标题元素 |
| 15 | 中文字体 | 【推断，未实测】Newsreader/Inter 为拉丁字体，中文全部落到系统默认字体 | Windows/Android 上中文可能显示为黑体，与"衬线古风"不一致 | 在字体栈中显式加入中文衬线回退（如 "Noto Serif SC", "Songti SC", serif），不必引入 webfont |
| 16 | 日志列表 | 【主观】8 页只能顺序翻页，无分类/年份筛选 | 想找某一类手记（人物手记 vs 外传）困难 | 列表顶部加分类标签筛选或按年份归档 |

## 4. 重点改善方向

**视觉设计**：保持纸本+水墨基调；修复暗色模式的对比度（#2、#13）；统一按钮选中态语言（#12）；为中文补衬线字体回退（#15）。

**页面布局**：分类列表与百科首页改为网格（#1、#8）；词条页加章节锚点（#5）；首页百科区展示精选或分类入口（#7）。

**导航与信息架构**：全局搜索入口（#3）；百科与日志分类边界划清（#8）；搜索结果加类型标识与排序优化（#4）；统一中文用语（#10）。

**交互体验**：搜索精确匹配优先；表格横滑提示；日志筛选（#16）。

**响应式/移动端**：表格溢出与滑动提示（#6）；移动菜单加搜索（#3）；首页 iframe 懒加载减流量（#9）。

## 6. 总结

**整体评价**：视觉定位准确、阅读体验扎实（字号、行高、对比度、自动词条链接、双作品对比图表都做得好），是一个"内容做得很深、但入口做得很浅"的站点。主要短板集中在**信息查找路径**：分类浏览靠翻页、搜索只在一个页面、长词条无目录；另有暗色模式与移动端表格的实际缺陷。

**最值得优先改善的 5 项**：

1. 修复暗色模式下按钮文字不可见（成本最低、影响直接）
2. 分类列表改为大容量网格（解决 56 页问题）
3. 顶栏全局搜索 + 结果标注类型
4. 词条页章节锚点目录
5. 移动端表格溢出与横滑提示

**整体优化方向**：不做重设计，保留纸本水墨风格，围绕"更快找到词条"重构入口层（百科首页、分类页、搜索、词条内导航），并把暗色与移动端补齐到与亮色桌面同等质量。
